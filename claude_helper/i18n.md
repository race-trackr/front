# Internationalisation (i18n)

Configurée dans [src/i18n.ts](../src/i18n.ts). Framework : **i18next** + **react-i18next**.

---

## Langues supportées

| Code | Langue           | Fichier                           |
| ---- | ---------------- | --------------------------------- |
| `en` | Anglais (défaut) | `src/locales/en/translation.json` |
| `fr` | Français         | `src/locales/fr/translation.json` |
| `es` | Espagnol         | `src/locales/es/translation.json` |
| `it` | Italien          | `src/locales/it/translation.json` |

---

## Règle absolue

**Toute chaîne visible par l'utilisateur doit utiliser `t('clé')`.**
Cela inclut : labels, placeholders, messages d'erreur, textes de boutons, titres, descriptions.

Avant d'utiliser une clé, l'ajouter dans **les 4 fichiers de locale** simultanément.

---

## Usage dans les composants

```typescript
import { useTranslation } from 'react-i18next';

const MyComponent = () => {
  const { t, i18n } = useTranslation();

  return (
    <Button>{t('save')}</Button>
  );
};
```

### Interpolation de variables

```typescript
// Fichier JSON
{ "session_of_date": "Session du {{date}}" }

// Composant
t('session_of_date', { date: formattedDate })
```

## Détection automatique de la langue

`i18next-browser-languagedetector` lit la langue depuis :

1. `localStorage` (choix précédent de l'utilisateur)
2. En-tête `Accept-Language` du navigateur
3. Fallback : `en`

Le `LanguageSwitcher` permet de changer la langue manuellement. Elle est alors persistée dans `localStorage`.

## Formatage des dates avec locale

Quand on formate une date, passer la locale i18n correspondante à `date-fns` :

```typescript
import { format } from 'date-fns'
import { fr, enUS, es, it } from 'date-fns/locale'

const getLocale = (lang: string) => {
  switch (lang) {
    case 'fr':
      return fr
    case 'es':
      return es
    case 'it':
      return it
    default:
      return enUS
  }
}

// Dans le composant
const { i18n } = useTranslation()
format(new Date(trackday.date), 'PPP', { locale: getLocale(i18n.language) })
// → "12 janvier 2025" en français, "January 12, 2025" en anglais
```

Cette fonction `getLocale` est définie dans `App.tsx` et utilisée dans les loaders pour les breadcrumbs dynamiques. La **reproduire localement** dans les composants qui en ont besoin — ne pas importer depuis `App.tsx`.

## Hors du contexte React (stores, utils)

Pour utiliser `t()` en dehors d'un composant React (ex: dans `authStore.ts`) :

```typescript
import i18n from '@/i18n'

showSuccess(i18n.t('logged_in_successfully'))
```

## Ajouter une nouvelle clé de traduction

1. Identifier la clé sémantique en anglais (snake_case) : ex. `delete_vehicle_confirm`
2. Ajouter dans `en/translation.json` : `"delete_vehicle_confirm": "Are you sure you want to delete this vehicle?"`
3. Ajouter dans `fr/translation.json`, `es/translation.json`, `it/translation.json`
4. Utiliser `t('delete_vehicle_confirm')` dans le composant

Ne jamais laisser une clé manquante dans une locale — i18next affiche la clé brute si la traduction est absente.
